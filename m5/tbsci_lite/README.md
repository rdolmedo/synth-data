# m5/tbsci_lite: synthetic SFT data for TB-Science-lite (#353, M5 of #53)

Problems only: no references, rubrics, tests or verifiers. Super writes one trace per problem, using the
lite eval's own harness. Data root: `/data/aai/m5/tbsci_lite/`.

## Pipeline

| Step | Code | Notes |
|---|---|---|
| Base image | `base_image/` | `local/tasksynth-sci:1`: M1's `tasksynth-base:2` plus the science stack (numpy, scipy, pandas, scikit-learn, statsmodels, astropy, biopython, rdkit, ase, xarray, netCDF4, h5py, cvxpy, ortools, numba, ...), R, ngspice, gfortran. One shared base; per-task apt/pip goes in thin layers through the package cache. This replaces the design's "~8 field bases" (coordinator OK, 2026-11-12). |
| Vocabulary | `vocab.py` -> `vocab.json` | Top level fitted to lite's 135 retained v2.1 tasks: domain shares, then the field within each domain (+1 smoothing, 17 fields). Archetype and modality come from class-level Opus labels of lite, smoothed toward the pooled mix; vocab v3 adds lite's joint `modality_by_archetype` (op `joint`), because in lite the main data follows the kind of work (design 83% model-spec, fit/infer about 0%). Opus brainstormed about 120 subtopics per field (2,045 in all) and the formats per field; no lite task was ever in a brainstorm prompt. Then a check: Opus, given each lite task, names its subtopics. The 16 subtopics judged specific to a single lite task were broadened or merged (`singles_log`). 3% open draws. |
| Specs | `specs.py`, `plan.py` | Each spec draws field -> subtopic, archetype, then modality given the archetype (v3), and format, and a target time: `--minutes v1` = 2/3/4/6 h at 35/30/20/15% (production), or the vocab's 4/6/8/12 h mix (v2a; Super then submitted only 49%, below the 60% gate). About 24% are real-data specs bound to a scidata dataset of the same field, steered to data-driven archetypes. `--ms-boost F` multiplies P(model-spec given archetype) (prod3: 1.8), since authors turn about a third of planned model-spec specs into dataset tasks. Datasets bound in earlier rounds go after unused ones. |
| Generator | `prompts.py`, `round_sci.py` | M1's round driver (task-synthesis e9ce566): one-shot author, the same output blocks, package checks, harbor_ns build, offline sandbox checks, up to 2 repair turns and the LLM judge. Changes from M1: a science system prompt (prompts v2: the spec's kind of work and main data define the task; model-spec tasks ship a specification and no dataset; a few hundred lines of careful code plus validation; hidden truth never readable; explicit acceptance criteria); one judge-repair turn (`--judge-repairs 1`: the judge's issues go back to the author, the package is rebuilt, rechecked and rejudged; prod2 acceptance 78% vs 65%); `--gen/--judge alloc:ds` follows `alloc.json` ds.serving across server swaps; a judge sentence on hidden-truth leaks; a 50 MB data ceiling; lite's closing sentence ("You have N seconds ...", N drawn from the eval's mix); DeepSeek requests kept under the `alloc.json` cap; transport errors retried for about 1 h. The generator runs DeepSeek V4.1 Flash with no output cap, a 6 h timeout and high effort for both author and judge. |
| Real data | `scidata.py` | Shared cache `/data/aai/m5/shared/scidata/`. Zenodo datasets are found by subtopic query: open licence, no ND, at most 20 MB. Blocked: any file whose SHA-256 matches a lite file, and any DOI, Zenodo id or URL a lite task cites. A DeepSeek fit check follows. The author is shown M1's manifest plus NetCDF/HDF5/FITS/NPY structure. Each dataset records its URL, DOI, licence and per-file SHA-256. |
| Traces | `traces.py` | The lite eval's pi_eval protocol (`aa_evals/tbsci_lite/pi.py`): Pi 1.2.0 pi180, 131,072 context, submit at the limit, 16,384 output per request, the registry's request block, a 2 h environment-clock cap, offline agent, multi-uid, NsSidecarEnvironment, MEMCAP 1.5 and CPU view. It runs over chunks of accepted tasks on the coordinator's Super engines. Per-engine in-flight shares follow one rule across all drivers (oldest chunk first, within `alloc.json`'s cap; `RUN/control.json`). New chunks are packed on the most-loaded engine with room. A chunk on an engine that leaves `alloc.json` is orphaned after 10 min (workers removed, unfinished tasks requeued); runs get extra 16-slot workers when their share exceeds their slots, and finished runs' workers are removed. Worker scratch full (ENOSPC, per-task images; `HARBOR_NS_EVICT_IDLE_H=0.25`): workers are replaced and infra-failed tasks requeued (at most 2 times). Stop rules: `--target-tokens` (STOP to the rounds; pending tasks are still traced) and the tail rule `--stop-total` / `--tail-inflight` (stop launching, remove live workers). |
| Export | `export.py` | Writes the synth/archive layout that `sft_qwen35/prepare.py --source pi_native --synth-roots` reads (teacher `nemotron35-super`). Every finished trace is kept and flagged by its end (submitted / context_limit / env_budget / stopped). `export combine` merges the driver exports into one root (one trace per task; `--budget` keeps whole traces of a seeded random order of tasks up to the token budget; shards rewritten verified, with index and SHA256SUMS). `prep_dryrun.sh` is the CPU dry run of the prep. |
| Decontamination | `decontam.py`, `rubric_reuse_lite.md`, `decon_controls.py`, `decon_final.py`, `decon_job.sh` | Final run 2026-11-17 (`/data/aai/m5/tbsci_lite/decon-final/`, code ce00de6a): the #119 pool method with lite (all 141 pool tasks) as the reference set over every traced task (3,821 incl. 8 planted positive controls; 3,673 in the SFT mixture). Windows on instr, instr+tests, embed, overlap (8-gram/identical files) and forced, plus each task vs its nearest lite task; lite bundles capped at ~58k tokens (uncapped, 38 overflowed the judge's context). DeepSeek judge, 2 samples (+6 when not NO_REUSE twice); 24,754 pairs, 49,676 samples. `excluded.json`: 1 mixture task (s102-01635, same Visium kidney dataset as spatial-rna-decontamination's calibration backbone, 1 of 8 samples REUSE); controls 8/8; no canaries. |
| Metrics | `report.py`, `vocab.py label-generated` | Funnel, instruction stats against lite, taxonomy spread against targets, TF-IDF repeat meter projected to production, 8-gram copying of the prompt material, trace endings and tokens. |

Jobs run from frozen worktrees: `common.frozen_checkout()` for this branch, and `/data/aai/m5/tbsci_lite/code/ts-e9ce566`
(task-synthesis), `code/ds-60f67da` (data-synthesis decontam) and `code/sft-0538ea6` (sft prep), all under `/data/aai/m5/tbsci_lite/code/` (home is a small quota).
gpu123 never writes bulk data to /data: run creation, exports and downloads all happen in CPU jobs (`job.py`).

## Commands

```bash
export PYTHONPATH=<ts checkout>:<this branch>
python -m m5.tbsci_lite.plan --round prod3 --n 1800 --seed 103 --minutes v1 --ms-boost 1.8
(cd <ts checkout> && $PY -m m5.tbsci_lite.round_sci submit --round prod3 --gen alloc:ds --judge alloc:ds \
    --reasoning-effort high --judge-effort high --effort-scope all --judge-repairs 1 --cpus 8 --memory-gib 48 --bid 36)
$PY -m m5.tbsci_lite.traces submit --name prod3 --rounds prod3 --chunk 100 --stop-total 327000000 --tail-inflight 50
$PY -m m5.tbsci_lite.report --rounds prod3 --traces prod3
$PY -m m5.tbsci_lite.vocab label-generated --rounds prod3 --limit 240        # spirit check (Opus labels vs lite)
$PY -m m5.tbsci_lite.job --name combine -- m5.tbsci_lite.export combine --out <root>/export/export-330m \
    --sources <root>/traces/{pilot,p0,v2a,prod1,prod2,prod3}/export --budget 330e6 --seed 353
```
